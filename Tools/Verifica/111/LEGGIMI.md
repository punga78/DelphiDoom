# Verifica #111: la GUI di Doom 3 (`.gui`)

Produce `Tests\Data\Gui\window\window.golden.txt` con il codice **vero** di Doom 3, non riscritto. Nessun file di Doom 3 e' nel repository: `Build-Harness.ps1` copia `neo\idlib`, `framework`, `renderer` e `ui` da `Reference\doom3\neo` in una cartella di lavoro, applica le modifiche e compila con `bcc32c` (il clang a 32 bit di Delphi 11, **senza** `-std=c++14`).

```
powershell -NoProfile -File Tools\Verifica\111\Build-Harness.ps1 -Neo <Reference\doom3\neo> -Work <cartella di lavoro> [-Scenarios window.input.txt] [-Output golden.txt]
```

- **Codice vero compilato**: `ui\Window.cpp`, `Winvar.h`, `RegExp.cpp`, `GuiScript.cpp`, `SimpleWindow.cpp`, `ChoiceWindow.cpp`, `SliderWindow.cpp`, `BindWindow.cpp`, `FieldWindow.cpp`; le funzioni di `idUserInterfaceLocal` dal costruttore a `Trigger` ritagliate per intervallo di righe da `UserInterface.cpp` (`InitFromFile`, `StateChanged`, `Activate`...); `idlib` (`Str`, `Token`, `Lexer`, `Parser`, `Dict`, `LangDict`, `math`, `hashing`, `HashIndex`) con le stesse modifiche del harness delle dichiarazioni (`Tests\Data\Decl\README.md`).
- **Tolti da `Window.cpp` della copia**: i giochi (`gameSSDDef`, `gameBearShootDef`, `gameBustOutDef`), `listDef`, `markerDef`, `renderDef` (dipendono dal motore) e `editDef`: col contesto di dispositivo finto il costruttore del suo scroller (`idSliderWindow::InitWithDefaults`) si ferma. Le parole non sono confrontate dal C++ (hanno test Delphi).
- **Stub scritti per il test** (`harness\*.txt`): `driver.cpp.txt` (legge gli scenari, esegue le operazioni, scrive il dump), `ui_stubs.h.txt` (materiale, `sysEvent_t`, sessione e suono, cvar, tasti, gestore delle dichiarazioni con `FindMaterial`, `FindType` e `DeclByIndex`), `stubs.cpp.txt` (`idDeviceContext` senza disegno; `FindFont` numera i font dal 1 in ordine di richiesta), `build.ps1.txt` (la compilazione a mano usata mentre si scriveva l'harness). Il `precompiled.h` e' quello di `Tests\Data\Decl\harness\material` con le modifiche di `Build-Harness.ps1`.
- **Scenari** (`Tests\Data\Gui\window\window.input.txt`, scritti per il test): righe `@case`, `@file` (le righe fino alla direttiva dopo), `@op` con `load`, `frame T`, `state CHIAVE VALORE`, `statechanged T`, `named NOME`, `activate 0|1 T`, `trigger T`, `dump`; il resto e' libero. `frame` fa `SetTime` e `RunTimeEvents` sul desktop (cio' che fa `Redraw` senza disegnare).
- **Formato del dump**: `I interactive pending`, poi per ogni finestra `W nome flags simple child draw scr tl named tr upd cmd` e le righe di rettangolo e colori (float come bit esadecimali), scala del testo, rotazione, visibilita', testo, sfondo, le variabili definite (`var nome = testo`) e per choice e slider `X ...`; una finestra semplice ha le sole righe di `idSimpleWindow` (`S ...`). Le righe `W:` sono gli avvisi di `common->Warning` (`P:` i messaggi).
- Il test Delphi `TTestGuiWindowParity` (`Tests\Source\DelphiDoom.Tests.Gui.WindowParity.pas`) rifa gli scenari con le classi di `Libs\Gui` e confronta riga per riga **senza tolleranza**; se non coincide scrive `DelphiDoom.Tests.Gui.window.actual.txt` accanto all'eseguibile.
- **Difetti del C++ trovati** (dettaglio nel README di `Libs\Gui`): `Script_SetFocus` senza parametri legge fuori dalla lista (`assert` di `idList`: l'harness si ferma, per questo lo scenario `errors` usa `evalRegs "x"`), il ramo `else` complesso di `?:` vale 0, un nome non legato citato in un'espressione azzera la variabile.
- Il C++ di Doom 3 non e' nel repository (`Reference\doom3` e' ignorato da git): solo i quattro file scritti per il test, lo script e i dati.
